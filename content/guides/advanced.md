## ① 이 과정의 대상

이런 분에게 맞습니다.

- 중급 과정 수준으로 설정·프로브·자원을 다룰 수 있다.
- 여러 팀이 함께 쓰는 클러스터에서 권한·네트워크·보안 기준을 정해야 하는 개발자 또는 운영자다.
- 스케줄링, API 확장(CRD), 클러스터 수명 주기까지 운영 구조를 이해하고 싶다.

선수 지식이 부족하다면 먼저 보세요.

| 부족한 부분 | 참고 |
|---|---|
| 매니페스트 작성과 장애 진단이 아직 어렵다 | [중급 종합 과제](#/item/i-cap) |
| Service·라벨·DNS 동작이 헷갈린다 | [첫 Deployment·Service](#/item/b-lab01) |
| 인증과 인가의 차이를 모른다 | [RBAC 실습](#/item/a-lab01)의 개념 절을 먼저 읽습니다. |

이 과정의 NetworkPolicy 실습과 종합 과제는 **별도 minikube 프로필(`k8s-lab-calico`)**이 필요합니다. 만드는 방법과 이유는 해당 실습 맨 앞에 있으며, 생성에 약 5~10분이 추가로 걸립니다.

## ② 완료 후 할 수 있는 일

- 앱마다 필요한 권한만 가진 ServiceAccount를 만들고, `kubectl auth can-i`와 실제 토큰으로 경계를 검사합니다.
- 기본 ClusterRole(view·edit)을 한 네임스페이스에만 안전하게 재사용합니다.
- NetworkPolicy가 CNI에 의해 집행된다는 점을 이해하고, 기본 차단 위에 필요한 통신만 엽니다.
- `namespaceSelector`·`podSelector`의 AND/OR 차이로 생기는 과다 허용을 찾아냅니다.
- Pod Security의 restricted 기준을 네임스페이스에 적용하고, 기준을 통과하는 securityContext를 작성합니다.
- 스케줄링 제어, CRD·Operator, 업그레이드·복구를 다룹니다. (예정 콘텐츠 공개 후)

## ⑤ 권장 학습 방법

1. **개념 읽기**: 보안 기능은 「무엇을 막는가」보다 「무엇을 허용하는가」로 정의됩니다. 허용 목록 관점으로 읽으세요.
2. **결과 예상하기**: 허용·거부 결과를 실행 전에 표로 적습니다. 예상과 다르면 그 이유가 곧 학습 포인트입니다.
3. **직접 실행하기**: 컨텍스트를 자주 바꾸므로 명령 블록 위의 「컨텍스트 k8s-lab-calico」 표시를 확인합니다.
4. **결과 확인하기**: 거부 메시지(Forbidden, PodSecurity)는 원인을 정확히 알려 줍니다. 메시지를 끝까지 읽습니다.
5. **응용 과제**: 일부러 과다 허용을 만들어 보고 탐지 방법을 익힙니다.
6. **정리**: 권한 객체와 토큰이 든 파일까지 지웠는지 확인합니다.

### 과정 수료 체크리스트

- [ ] Role·ClusterRole·RoleBinding·ClusterRoleBinding의 조합별 효력 범위를 설명할 수 있다
- [ ] Forbidden 메시지에서 주체·동작·자원·네임스페이스를 읽어 낼 수 있다
- [ ] NetworkPolicy가 효과 없이 무시되는 환경을 구분할 수 있다
- [ ] egress 기본 차단 시 DNS를 열어야 하는 이유를 안다
- [ ] restricted 기준이 요구하는 securityContext 항목을 말할 수 있다
- [ ] 고급 종합 과제의 두 성공 판정을 통과했다
