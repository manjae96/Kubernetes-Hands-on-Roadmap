## ① 이 과정의 대상

이런 분에게 맞습니다.

- Linux 터미널에서 파일을 다루고 명령을 실행할 수 있다.
- `docker run`으로 컨테이너를 띄워 보았고, 이미지·태그·포트 개념을 안다.
- Kubernetes는 처음이거나, 튜토리얼을 따라 해 봤지만 구성 요소가 어떻게 이어지는지는 잘 모른다.

선수 지식이 부족하다면 먼저 보세요.

| 부족한 부분 | 참고 |
|---|---|
| 실습 클러스터가 없다 | [환경 준비](#/item/setup) (필수) |
| 컨테이너·프로세스·포트가 헷갈린다 | [리눅스와 컨테이너 복습](#/item/prep-linux-container) |
| YAML 들여쓰기가 낯설다 | [YAML과 매니페스트 읽기](#/item/prep-yaml) |

## ② 완료 후 할 수 있는 일

- 클러스터의 컨트롤 플레인과 노드 구성 요소를 kubectl로 확인하고 각 역할을 설명합니다.
- YAML 매니페스트로 웹 앱을 Deployment로 배포하고 Service로 하나의 주소에 묶습니다.
- 레플리카 수를 바꾸고, 파드가 지워져도 다시 채워지는 이유를 제어 루프로 설명합니다.
- 라벨과 셀렉터로 원하는 자원만 골라 조회합니다.
- 이미지 버전을 무중단으로 올리고, 잘못된 배포를 이전 버전으로 되돌립니다.
- `ImagePullBackOff`·`CrashLoopBackOff`를 이벤트와 로그로 진단합니다.

## ⑤ 권장 학습 방법

실습 단계마다 다음 순서를 지킵니다.

1. **개념 읽기**: 실습 앞부분의 「무엇인가 · 왜 필요한가 · 어떻게 동작하나」를 읽고 구성도를 봅니다.
2. **결과 예상하기**: 명령을 실행하기 전에 「예상해 보세요」에 답을 적습니다. 틀린 예상이 가장 많이 배우는 순간입니다.
3. **직접 실행하기**: 복사 버튼으로 명령을 가져오되, 코드 블록 위에 적힌 실행 셸을 확인합니다.
4. **결과 확인하기**: 출력을 예시 출력·검증 출력과 비교합니다. 이름 접미사·IP·시간은 달라도 됩니다. 「성공 판정」 상자에 출력을 붙여 넣으면 **실행 결과 확인됨**으로 기록됩니다.
5. **응용 과제**: 해설을 펼치기 전에 최소 10분은 스스로 시도합니다.
6. **정리**: 「정리와 재실행」의 명령으로 실습 자원을 지우고, 무엇을 배웠는지 세 줄로 적습니다.

### 과정 수료 체크리스트

- [ ] `kubectl get pods -n kube-system` 출력에서 컨트롤 플레인 구성 요소를 짚을 수 있다
- [ ] Deployment·ReplicaSet·Pod의 관계를 그림으로 그릴 수 있다
- [ ] Service가 파드를 찾는 방법(라벨 셀렉터)과 엔드포인트 확인 명령을 안다
- [ ] `kubectl scale`과 파일 수정 후 `kubectl apply`의 차이를 설명할 수 있다
- [ ] 롤링 업데이트 중 서비스가 끊기지 않게 하는 설정을 안다
- [ ] 배포 실패 시 `describe` → 이벤트 → 로그 순서로 원인을 찾을 수 있다
- [ ] 기본 종합 과제의 성공 판정을 통과했다
